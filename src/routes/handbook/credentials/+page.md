## 9.1 Verifiable Credentials & Blockchain Snapshots

Every completed level, project, and assessment produces a tamper-proof, verifiable credential that serves as the permanent record of capability.

- **Format:** W3C Verifiable Credentials (VC) in JSON-LD standard, with an additional cryptographic snapshot for immutability.
- **Credential contains:** learner DID (decentralized identifier), concept/level, mastery score, date, reviewers involved, blockchain hash, and linked evidence (project artifacts, assessment IDs).
- **Blockchain Snapshot Mechanism:** Every 24 hours (or on major milestones), the platform batches new credentials and publishes a Merkle-root hash to Polygon (low-cost, eco-friendly layer-2) or Ceramic Network. The full record remains in SurrealDB for fast queries, but the hash ensures no retroactive changes are possible — directly implementing the “impossible to tamper with scores or history” requirement from Section 10.

### Technical storage (SurrealDB)

```surrealql
DEFINE TABLE credential SCHEMAFULL;
DEFINE FIELD learner ON credential TYPE record(user);
DEFINE FIELD concept ON credential TYPE record(concept);
DEFINE FIELD score ON credential TYPE float;
DEFINE FIELD reviewers ON credential TYPE array<record(user)>;
DEFINE FIELD blockchain_hash ON credential TYPE string;
DEFINE FIELD issued_at ON credential TYPE datetime DEFAULT time::now();
```

### Privacy & revocation

- Learner controls visibility (private / public / share-with-specific-employer).
- Revocation possible only by the learner (e.g., if they want to hide an old low score) — the blockchain hash still proves the original record existed.
- No central authority can revoke or alter a credential.

This design makes credentials stronger than traditional degrees: instantly verifiable by any employer or institution without contacting Klados.

## 9.2 Learner Public Profile

The public profile is the single source of truth for what a learner can do. It replaces the résumé and is the primary interface for real-world linkage.

### Core fields (`user_profile`)

- Display name / pseudonym (optional real name with verification badge).
- Current mastery levels across all domains (e.g., “Mathematics Level 15 • Physics Level 12 • Programming Level 18”).
- Completed projects (with thumbnails, GitHub links, and reviewer quotes).
- Verifiable credentials list (sortable by date/domain).
- Reputation & Reviewer Rank (if applicable).
- Security Circle strength (trust score, anonymized).
- Bio / goals (optional, evidence-based only — no demographic fields).
- “What Can You Do?” summary generated by AI from the graph (e.g., “Ready for Data Scientist roles requiring ML Level 10+”).

### Privacy controls (granular, per-item)

- Toggle each credential or project public/private.
- “Employer View Only” mode (shareable link expires or requires one-time access code).
- Zero demographic data ever stored or displayed (Section 2.4.4).

UI Implementation (SvelteKit): Clean dashboard with Cytoscape mini-graph showing the learner’s personal mastery subgraph. One-click “Generate Shareable Portfolio PDF” or JSON-LD export.

## 9.3 Course Profiles (High-School, Degree Equivalents)

Course Profiles are community-defined, version-controlled templates that map the knowledge graph to traditional qualifications. They allow institutions to adopt Klados without rebuilding their systems.

### Structure

- Name (e.g., “Equivalent to Indian Class 12 / CBSE” or “B.Tech Computer Science – Full Degree”).
- Required concepts + minimum levels (e.g., Mathematics Level 12, Physics Level 8, Chemistry Level 8, Programming Level 14, etc.).
- Total estimated mastery time (AI-calculated, not binding).
- Issuance rule: All required levels completed + final capstone project reviewed.

### Examples

- High School Graduation Equivalent
- Bachelor’s in Data Science
- Master’s-level Machine Learning Specialization
- Vocational Robotics Technician Certificate

**Governance:** Any verified educator/reviewer can propose a new profile. Community vote + admin approval publishes it. Profiles are versioned; old versions remain for historical learners. Institutions can fork and customize for their needs (enterprise license revenue stream – Section 2.4.1).

## 9.4 Job Profiles (Company-Defined Competency Requirements)

Job Profiles are the direct bridge to employment and the primary revenue engine (companies pay for priority matching and verified talent pipelines).

### Structure (`job_profile`)

- Company name / anonymous posting option.
- Role title + description.
- Required minimum levels per domain (e.g., Data Scientist: Mathematics 15, Statistics 12, Programming 14, Machine Learning 10, Communication 8).
- Preferred (but not mandatory) levels and projects.
- Salary range / location / remote flag (optional).
- “Match My Levels” button for learners.

### Workflow

1. Companies create profiles via a simple web form (free basic tier; premium for verified hiring pipeline).
2. AI instantly ranks all public learners who match ≥90% of requirements and notifies top matches (with consent).
3. Learner shares their profile/credential directly with the company.
4. Platform earns a small, transparent success fee only when a hire is confirmed (optional mutual feedback).

This turns hiring into a skills-first process, solving the talent-shortage problem (Section 3.1.6) while generating sustainable revenue without ever charging learners.

## 9.5 Export & Sharing Mechanisms

Every credential and profile can be exported or shared in multiple formats for maximum real-world utility:

- **One-click PDF Portfolio** — branded document with graph visualization, credentials, and projects.
- **JSON-LD + VC Export** — machine-readable for ATS systems, university portals, or blockchain wallets.
- **Shareable Links** — time-limited or password-protected URLs.
- **QR Code** — for offline events, interviews, or printed résumés.
- **Embedded Badge** — for personal websites, LinkedIn, or GitHub profiles (Open Badges 3.0 compatible).
- **API Access (future Phase 3)** — authorized partners (universities, companies) can query public profiles via secure token.

All exports include the blockchain hash for instant third-party verification.

### Minute features

- “Add to LinkedIn” button that auto-fills experience with verified Klados credentials.
- “Capability Heatmap” widget embeddable on any site.
- Version history viewer showing how the profile evolved over time.
- Anonymous mode for job applications (hide name until interview stage).
- Bulk export for entire learning history (useful for university equivalency applications).

These credentials and profiles transform the question “What can you do?” from a vague interview prompt into a globally verifiable, instantly shareable fact — fulfilling the long-term vision (Section 2.1) and closing the loop between learning and opportunity.
